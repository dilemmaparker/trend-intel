Google Trends returns a 0–100 relative interest index, not raw search counts. This tool computes a composite score from three components — Volume, Momentum, Recency — weighted to generate buying mandates.

Scoring model
1
Volume (weight: 30%)
Anchor-normalised mean interest. Divides the concept's average by the parent category average (e.g. "kurti", "ethnic wear india") to correct for scale differences between garment categories.
volume = min(100, (mean(series) / mean(anchor)) × 100)
2
Momentum (weight: 40%)
Linear regression slope across the entire time window, normalised by mean interest. A slope of +2 on a term averaging 5 is more significant than +2 on a term averaging 80.
slope, _ = polyfit(time_index, series, degree=1) momentum = clip((slope / (mean + ε)) × 1000 + 50, 0, 100)
3
Recency (weight: 30%)
Compares last quarter of the time window against the first quarter. Captures whether interest is accelerating in the recent period specifically.
recency = clip((mean(last_25%) / (mean(first_25%) + ε) − 0.5) × 66.7, 0, 100)
4
Velocity (alert trigger)
Raw index-point difference between last and first quarters. Used as the alert threshold trigger.
velocity = mean(last_25%) − mean(first_25%) [in Google Trends index points]
5
Pearson correlation — time vs interest
Linear monotonicity between the time sequence [0,1,2,...,n] and the interest values. High positive = consistently rising. Note: late-stage viral breakouts score lower on this despite strong velocity.
corr = corrcoef([0,1,...,n], interest_values)[0,1]
6
Composite score & mandate
score = volume×0.30 + momentum×0.40 + recency×0.30 [BUY] score ≥ 65 AND velocity > 3 [BUY/HOLD] score ≥ 65 [HOLD] score ≥ 40 AND velocity > 1 [HOLD/WATCH] score ≥ 40 [WATCH] score ≥ 20 AND velocity > 0 [EXIT] everything else

Step-by-step guide to deploy this tool as a working public website. Recommended option: Render.com free tier — your Flask backend + this HTML frontend, live in ~20 minutes, free forever.

Step-by-step deployment
1
Make sure you have these 3 files in one folder
Download the files Claude generated: api.py, index.html, requirements.txt. Put them all in one folder, e.g. trendintel/. Also copy your existing trend_intelligence.py into that same folder.
2
Test locally first
Open a terminal, navigate to the folder, then run:
cd trendintel pip install -r requirements.txt python api.py
Open http://localhost:5000 in your browser. All buttons should now call the real backend. Test a scan to confirm data loads.
3
Create a free GitHub account and upload your files
Go to github.com → Sign up (free) → New repository → name it "trend-intel" → upload the 4 files: api.py, index.html, requirements.txt, trend_intelligence.py
Or if you have Git installed, run this in your terminal:
git init git add . git commit -m "initial deploy" git branch -M main git remote add origin https://github.com/YOUR_USERNAME/trend-intel.git git push -u origin main
4
Deploy for free on Render.com
Go to render.com → Sign up with GitHub → Click "New +" → "Web Service" → Connect your GitHub repo → Fill in these settings:
Name: trend-intel Runtime: Python 3 Build command: pip install -r requirements.txt Start command: gunicorn api:app
Click "Create Web Service". Render builds your app automatically. Takes about 3–5 minutes. Your live URL will be: https://trend-intel.onrender.com
5
Your app is now live. Share the URL.
Open the Render URL in any browser — your full app with real Google Trends data is live. Share this URL with your college supervisor or retail team. The free Render tier "sleeps" after 15 min of no traffic (takes ~30 seconds to wake up on next visit) — this is fine for demos.
6
Optional: Add login so only your team can use it
Add these lines at the top of api.py to password-protect the app:
from flask_httpauth import HTTPBasicAuth from werkzeug.security import generate_password_hash, check_password_hash auth = HTTPBasicAuth() users = {"admin": generate_password_hash("yourpassword123")} @auth.verify_password def verify(username, password): if username in users and check_password_hash(users[username], password): return username # then add @auth.login_required above every @app.route
7
If anything breaks — common fixes
Error "No data found": Google Trends blocked the request. Wait 10 minutes and try again with a simpler term (just "kurti" not "rust linen kurti").

App not loading on Render: Check the Render dashboard logs — usually a missing package. Add it to requirements.txt and push to GitHub again.

"pytrends not installed": Make sure requirements.txt has pytrends==4.9.2 and re-deploy.

Rate limit errors in watchlist: The watchlist runner waits 8 seconds between items. For large watchlists (10+ items), run off-peak hours.

Graduation Project · 2025
Data-Centric: Resource-Efficient AI Framework
for Competitive Value Retail
An AI-based trend forecasting system built during a 16-week internship (Dec 2024 – Apr 2025) at an ethnic value retail company in India. Born from a real gap observed on the buying floor.
The problem observed
Selection based solely on historic sales
The buying team relied on past bestsellers and STR data — no visibility into emerging consumer search demand.
High cost of commercial forecasters
WGSN, Trendalytics etc. start at ₹5–15L/year — inaccessible for value retailers with thin margins.
No regional granularity
National trend reports don't show how demand for block print differs between West Bengal and Gujarat.
Qualitative guesswork
Decisions relied on Pinterest, competitor floor walks, buyer intuition — no data backbone.
The solution
Open-source Google Trends data
Zero licensing cost. Search demand as a proxy for consumer intent.
Regional granularity at state level
8 Indian state filters — compare how a trend performs across regions before buying.
Quantified buying mandates
BUY / HOLD / WATCH / EXIT based on velocity and correlation — removes gut-feel from OTB.
Lean & sustainable buying
Exit signals prevent over-buying declining trends — reduces markdowns and working capital lock-in.
